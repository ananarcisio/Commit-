1. Criar o repositório

2. Repositório privado

Se o repositório for privado, o avaliador não consegue ver o código sem convite.

3. Documentação no GitHub

Estrutura recomendada:

commit-projeto/
├── README.md        ← objetivo, como rodar, prints
├── CHANGELOG.md     ← o que mudou em cada versão
├── docs/            ← diagramas, decisões técnicas
│   └── decisoes.md
└── src/             ← código-fonte

4. Envio final

Modelo de dados: Desafio

Mapeamento em formato de diagrama de classe, com atributos, ações e classes associadas.

┌───────────────────────────────┐
│           Desafio             │
├───────────────────────────────┤
│ id                            │
│ titulo                        │
│ resumo                        │
│ nivel  (Iniciante/Int./Avanç.)│
│ trilha (Front-end, SaaS...)   │
│ tempoEstimado                 │
│ tecnologias[]                 │
│ habilidades[]                 │
│ preRequisitos[]               │
│ entregaveis[]                 │
│ totalConclusoes               │
│ mediaAvaliacao                │
├───────────────────────────────┤
│ salvar() / remover()          │
│ iniciar()                     │
│ marcarItemConcluido()         │
│ avaliar(nota, comentario)     │
│ abrirTroubleshooting()        │
└───────────────────────────────┘

Associações:
  Trilha ─1..N─ Desafio
  Usuario ─N..N─ Desafio  (via Progresso: status, checklist, dataInicio)
  Desafio ─1..N─ Avaliacao
  Desafio ─1..N─ Recurso          (guia, tutorial, referência)
  Desafio ─1..N─ Troubleshooting  (problema, causa, solução)
  Desafio ─1..N─ ProjetoComunidade (votos)
  Desafio ─1..N─ Gabarito         (cadastrado pelo professor)

Ao usar o Commit!, você concorda com os Termos de Uso e a Política de Privacidade.
